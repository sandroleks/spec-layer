Create docs in Figma, copy context into your coding agent, or publish a library for your repository.

Canvas documentation, Copy for AI, and publishing your first Figma file are available on Free. Free publishing includes 10 updates per calendar month. The CLI requires Node.js 22 or newer.

Document in Figma

  1. Open Spec Layer

    Install the plugin from Figma Community and run it in your design-system file.

  2. Select your source

    Select a component or component set to open its documentation options. For local variable collections and text styles, open Generate foundation docs in the sidebar.

  3. Choose what to document

    Choose the sections or sources you need and select Create docs. In the component screen, AI writing is optional: it assists the sections marked AI. Measurements, states, anatomy, and tokens come directly from Figma.

  4. Review changes in the Library

    Open Library and select Refresh library to check the sources. Review detected changes, then use Update documentation for one item or Update all docs for the changed docs.

Copy for AI

Copy for AI exports structured design context without making an AI request or consuming your writing allowance. You can copy directly from a selected component or a foundation source, without creating canvas docs first.

For a component, select Copy for AI in the footer. You get compact YAML with its properties, variants, states, anatomy, layout, and the token and style dependencies it uses. Paste that context into your coding agent with your implementation request.

button.ai.yaml · abbreviated synthetic exampleDownload full YAML 
component: { name: Button, related: [Icon] }
api:
  variants:
    Style: { options: [Filled, Outlined], default: Filled }
  states: [Enabled, Hovered, Disabled]
  booleans: { Show icon: { default: false } }
  slots: { Label: { type: text, default: Button } }

This is a synthetic Button example from the repository. The full file includes references, bindings, and the component’s foundation dependencies.

Copy a foundation source

In Generate foundation docs, use the copy button beside a variable collection or Text styles. This copies the selected source and its required local token dependencies as a compact Design Tokens Community Group (DTCG) JSON document.

Foundation JSON preserves token types, values, modes, and references supported by the export. The document’s report records anything the DTCG format cannot express. Component context remains YAML.

A copy action does not change the sources selected for canvas docs. To keep context focused, copy the collection or component your agent needs.

Publish & pull

A library is one Figma file, published for developers to pull with the CLI.

Publishing uploads the file’s foundation context and connected component contexts to Spec Layer. The CLI downloads that published bundle into your repository. It does not connect directly to Figma or generate UI code.

Free includes 1 published Figma file and 10 updates per calendar month. Pro includes up to 10 published files with unlimited updates under fair use. A first publish or a successful publish that changes the library uses one update. Failed publishes, unchanged republishes, and CLI pulls do not count. Publishing updates reset on the first day of each month at 00:00 UTC, separately from AI writing.

If you use all 10 free updates, the published library remains available to pull. Upgrade to Pro or wait until the next month to publish changes. Free libraries do not expire.

  1. Publish from the plugin

    Create docs for the components you want to include. Open Library, select Publish, then Publish library. When publishing finishes, select Copy setup command under Developer setup.

  2. Connect your repository

    Run the copied command from your project’s root directory. It already contains your library ID and pull key. The values below are placeholders.

    npx spec-layer setup --id lib_... --key sl_... --platform web

    Setup writes speclayer.json, stores the key in a gitignored speclayer.local.json, and pulls the artifacts into .speclayer/. Pass --platform web in a fresh directory so the first pull writes the tokens/ directory.

  3. Refresh your local context

    When the design changes, publish the library again from Figma. Then run the command below in your project to download the new version:

    npx spec-layer pull
Updates are explicit: publish in Figma, then pull in your repository. status compares against the last published library. It cannot see unpublished changes in Figma.

Files added to your project

.speclayer/
├── bundle.json          # published library bundle
├── manifest.json        # artifact hashes and file paths
├── tokens/              # Foundation DTCG record (CLI 0.4+)
└── outputs/             # output name maps and reports

component-specs/         # component briefs (CLI 0.7+)
└── <component-name>.yaml

tokens/                  # web token files (CLI 0.7+)
└── index.css

Point your coding agent at component-specs/ and .speclayer/tokens/. The bundle also retains the canonical artifacts when you need their full structure.

CLI versions: setup requires CLI 0.3.0 or later. Foundation output under tokens/ requires 0.4.0 or later. The path manifest field and platform outputs need 0.6.0 or later. component-specs/, componentSpecsDir, and the tokens/ directory need 0.7.0 or later. For automated workflows, install and pin the CLI as a development dependency.
