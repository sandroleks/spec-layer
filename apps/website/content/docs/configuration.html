Keep shared project settings in speclayer.json and access keys outside version control. Configure which outputs your repository needs.

The project file

Run commands from the folder containing speclayer.json. Setup creates this file; you can then edit its output selection and token options.

speclayer.json · example
{
  "libraryId": "lib_...",
  "outDir": ".speclayer",
  "include": {
    "foundation": true,
    "components": ["Button", "Text field"]
  },
  "dtcg": {
    "values": "standard",
    "units": {
      "Foundation/spacing/*": "px"
    }
  }
}

Replace the library ID and component names with your own. The unit pattern is illustrative; it only applies when your collection and variable names match.

FieldDefaultPurpose
libraryIdSet by setupThe library published from Figma.
outDir.speclayerA managed output folder inside your current directory.
include.foundationtrueWhether to write foundation token files.
include.componentsAll, when omittedAn array of component names. An empty array selects none.
dtcg.valuesstandardThe value representation used for token files.
dtcg.unitsNo overridesExplicit unit assignments for otherwise unitless numbers.

Choose what to pull

Without an include block, a pull writes the foundation and all components. Save a list in the project file to make later pulls use the same selection.

Command-line selection flags override that selection for the command. They replace it entirely rather than adding to it. setup and init save an explicit selection; pull applies one for the current run.

npx spec-layer pull --component Button
npx spec-layer pull --only components --component Button

The first command includes the foundation; the second excludes it. Both retain the full published bundle in bundle.json. Selection controls separate output files, not access to individual records.

Pull keys

setup stores your key in speclayer.local.json. Inside a Git working tree, it confirms the file is ignored before writing the key. Shared configuration and generated outputs do not contain that key.

For pull and status, key precedence is:

  1. --key
  2. The SPEC_LAYER_KEY environment variable
  3. The local key file, when it belongs to the selected library

Setup takes its key from --key or SPEC_LAYER_KEY. If a key changes, copy the new setup command from the plugin and run it again. Setup preserves existing output, selection, and token settings when no override is supplied.

To rotate a key, open Library → Publish and select Rotate key. Previous keys stop working within about a minute. Give the new setup command to every developer who needs access.

Token output options

dtcg.values accepts standard or legacy. Standard uses the 2025.10 object forms. Legacy uses string forms for integrations that expect them. Select the form supported by your token tooling.

dtcg.units maps a collection name plus a variable-name glob to px or rem. Use it to declare a unit for a number whose Figma scopes do not state one. Spec Layer does not infer a unit from the variable’s name.

"units": {
  "Foundation/spacing/*": "px",
  "Foundation/radius/*": "px"
}

An override that conflicts with an explicit source scope is ignored and reported in tokens/report.json. A changed dtcg block is applied by the next pull, even if nobody republished the library.

Use resolver.json to identify the token files for the mode you need. Exclude spec-layer.meta.json and report.json from patterns that select token files.

These options control the files generated by pull. show foundation prints the DTCG document stored in the bundle, rather than regenerating it with your local options.

Use in automation

Pin the CLI as a development dependency and provide SPEC_LAYER_KEY through your CI provider’s secret store. Keep speclayer.json alongside your project.

Run after dependencies and secrets are available
npx spec-layer status

Treat exit 0 as current, 2 as behind or not yet pulled, and 1 as an error requiring attention. Run pull when you want to update generated context. Do not treat every nonzero exit as stale data.

SPEC_LAYER_API overrides the default API origin for network commands; --api takes precedence. Keep the default unless you operate a different Spec Layer API.

Common setup issues

No local pull found
Run the setup command from the plugin or run pull from your configured project directory.
The key belongs to another library
Run the setup command for the library you want. A local key for a different library is not reused.
The key file is already tracked
Remove speclayer.local.json from Git tracking, keep it ignored, then run setup again. Rotate the key if it was shared.
The output directory is refused
Choose a new or empty folder inside your project, or use an existing Spec Layer output folder. Keep hand-written files elsewhere.
