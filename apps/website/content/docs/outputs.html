Extraction is deterministic. Previously saved AI-written guidance may accompany an export, but it is identified separately and excluded from semantic content hashes.

Component YAML

A component copy contains its properties, variants, states, anatomy, default-variant layout, and the token and style dependencies it uses. The dependency slice includes the local aliases needed to interpret those references.

Synthetic Button example · excerptDownload full YAML
component: { name: Button, related: [Icon] }
api:
  variants:
    Style: { options: [Filled, Outlined], default: Filled }
  states: [Enabled, Hovered, Disabled]
  booleans: { Show icon: { default: false } }
  slots: { Label: { type: text, default: Button } }

The compact profile has spec_layer.version: 5 and profile: ai. Its hashes refer back to canonical context. It is not the canonical JSON shape and should not be validated against that schema.

Reference status makes missing information explicit: resolved, external, unavailable, not_in_snapshot, not_extracted, or no_foundation. Join references by resource kind and source ID, not by display name.

Foundation DTCG JSON

Foundation copies use a Design Tokens Community Group (DTCG) resolver document. The CLI writes its file-based equivalent under tokens/, using the Design Tokens Format and Resolver Modules 2025.10.

Token files are organized by collection and mode. Typography and effect styles have dedicated files when present. resolver.json describes how to select the files for a mode.

{
  "$type": "color",
  "$value": {
    "alpha": 1,
    "colorSpace": "srgb",
    "components": [1, 1, 1],
    "hex": "#ffffff"
  }
}

spec-layer.meta.json retains source details such as Figma IDs and code syntax. report.json explains information the projection cannot express. These are sidecars, so exclude them from token-file globs.

Inspect the synthetic resolver and its linked files. For compatibility formats or explicit unit choices, see token output options.

The tree shows possible output. Token and component files depend on the published library and your selection. Component filenames are slugged; collisions receive numeric suffixes.

bundle.json
The published bundle, retained in full even when you select only some artifacts for separate files.
manifest.json
Library and publication information, bundle hash, output selection, and an index of artifact names, content hashes, and paths. An unselected artifact has aiPath: null.
tokens/ and ai/components/
The files your token tooling and coding agent usually read. The foundation entry’s manifest path points to tokens/resolver.json.

How updates affect files

The CLI stages output in .speclayer.partial and swaps it into place. Keep your own source files outside this managed output directory.

An unchanged bundle, selection, and token configuration produces no new writes. Republishing changes export IDs and timestamps, so the bundle and manifest can change even if their semantic content hashes stay the same.

Component YAML, token files, and semantic hashes stay stable when the facts they represent do not change. An unrelated foundation change can move the whole-foundation hash without changing a component whose dependency slice is unchanged.
