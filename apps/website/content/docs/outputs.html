Component YAML

A component copy contains its properties, variants, states, anatomy, default-variant layout, and the token and style dependencies it uses. The dependency slice includes the local aliases needed to interpret those references.

Synthetic Button example · excerptDownload full YAML
component: { name: Button, related: [Icon] }
api:
  variants:
    Style: { options: [Filled, Outlined], default: Filled }
  states: [Enabled, Hovered, Disabled]
  booleans: { Show icon: { default: false } }
  slots: { Label: { type: text, default: Button } }

The compact profile has spec_layer.version: 5 and profile: ai. Its hashes refer back to canonical context. It is not the canonical JSON shape and should not be validated against that schema.

Reference status makes missing information explicit: resolved, external, unavailable, not_in_snapshot, not_extracted, or no_foundation. Join references by resource kind and source ID, not by display name.

Foundation DTCG JSON

Foundation copies use a Design Tokens Community Group (DTCG) resolver document. The CLI writes its file-based equivalent under tokens/, using the Design Tokens Format and Resolver Modules 2025.10.

Token files are organized by collection and mode. Typography and effect styles have dedicated files when present. resolver.json describes how to select the files for a mode.

Synthetic semantic color · excerptDownload example
{
  "$type": "color",
  "$value": {
    "alpha": 1,
    "colorSpace": "srgb",
    "components": [1, 1, 1],
    "hex": "#ffffff"
  }
}

spec-layer.meta.json retains source details such as Figma IDs and code syntax. report.json explains information the projection cannot express. These files contain metadata, not tokens. Exclude them from patterns that select token files.

Inspect the synthetic resolver and its linked files. For compatibility formats or explicit unit choices, see token output options.

This example shows the files a pull can create. Token, component, and output files depend on the published library, your selection, and your outputs configuration. Component filenames are slugged; collisions receive numeric suffixes.

bundle.json
The published bundle, retained in full even when you select only some artifacts for separate files.
manifest.json
Library and publication information, bundle hash, output selection, and an index of artifact names, content hashes, and paths. An unselected artifact has path: null.
.speclayer/tokens/
The DTCG record your token tooling reads by path. The foundation entry’s manifest path points to .speclayer/tokens/resolver.json.
outputs/
Per platform output, the name map (web-css.map.json: DTCG path to emitted name, with code_syntax or derived as its source, and the file that declares it) and the report of what the format could not express.
tokens/
The web token files, written in place at the path in outputs: one file per collection and mode, sets and default modes at :root, other modes under [data-theme="…"] in their own files, aliases as var(), and index.css importing them in resolver order.
component-specs/
One YAML brief per selected component, byte-identical to Copy for AI, at componentSpecsDir.

Web token files

When platforms includes web, pull writes a tokens/ directory of custom-property files at outputs[].path (default tokens). Names use the designer’s code_syntax.WEB when Figma declares one and otherwise the DTCG path in the chosen case: kebab, camel, pascal, snake, or constant. Two tokens that would share a name are both omitted and reported. A number whose Figma scopes state no unit stays a bare number, and no mode name selects a media query. The directory is written only when that pull writes the Foundation; with --only components it is left as it was, and list shows it as “not written”.

tokens/index.css
/* Foundation */
@import "./foundation.css";
/* Mapped Colors, Light */
@import "./mapped-colors.light.css";
tokens/mapped-colors.dark.css
[data-theme="dark"] {
  /* Mapped Colors, Dark */
  --mapped-colors-surface-primary-default: var(--foundation-colors-blue-900);
}

The directory is written in place; pull replaces or removes only files that begin with its header and refuses to run when anything else is there. Commit it with .speclayer/ and speclayer.json. A repository that already builds tokens with Style Dictionary can keep reading .speclayer/tokens/; the CSS files are a projection of the same record, not a second source.

How updates affect files

The CLI stages output in .speclayer.partial and swaps it into place. Keep your own source files outside this managed output directory.

Pulling an unchanged published bundle with the same selection and token configuration produces no new writes. After a changed library is published, the next pull refreshes the bundle and manifest. CLI pulls do not use your publishing update allowance.

Component YAML, token files, and semantic hashes stay stable when the underlying design data does not change. An unrelated foundation change can change the whole-foundation hash without changing a component whose dependency slice is unchanged.

Output files declared under outputs are replaced in place, never deleted.
