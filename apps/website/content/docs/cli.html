Connect a published library, pull updates, and inspect the context in your repository. This reference covers CLI {{cliVersion}}.

Requirements and installation

Use Node.js 22 or newer and run commands from your project root. Publishing is available on Free and Pro; pulling a library requires its ID and pull key, with no Pro license required. For your first connection, follow the setup instructions before running pull.

After setup, pull the published library
npx spec-layer pull

For automated runs, pin the documented CLI version as a development dependency:

Install a specific version
npm install --save-dev --save-exact spec-layer@{{cliVersion}}

npx spec-layer then uses the installed local version. If you deliberately use an uninstalled package in automation, npx --yes spec-layer … suppresses npm’s installation prompt.

setup

Save the library ID, store the pull key locally, and perform the first pull. Copy the real command from Library → Publish → Copy setup command after publishing.

npx spec-layer setup --id lib_... --key sl_... --platform web

The values above are placeholders. Setup writes speclayer.json and speclayer.local.json. Inside a Git repository, it checks that the key file is ignored before writing the key.

Re-running setup replaces the stored key while preserving the output directory, selection, and token options unless you explicitly override them. If the first pull fails, the saved setup remains available; retry with pull.

The repeatable --platform flag stores which platforms this repository builds for. Without it, setup reads the repository root and stores a platform only when it finds a matching signal. A stored web platform gets a default token output, the tokens/ directory; other platforms are stored without one until a token format exists for them.

init

Write configuration without storing a key or making a network request. Use this when your key comes from an environment variable.

npx spec-layer init --id lib_... --out .speclayer --platform web

init overwrites speclayer.json. Use setup to replace a key while preserving existing settings.

init takes the same repeatable --platform flag as setup and stores platforms and a default output the same way.

pull

Fetch the last published library and write selected artifacts to the output directory. The default is .speclayer/.

Download the published version
npx spec-layer pull

The output must be inside the current directory. An existing non-empty directory that Spec Layer did not create is refused. With the same bundle, selection, and token options, an up-to-date pull writes nothing.

Design changes must be published from Figma before a pull can see them.

pull also takes a repeatable --platform flag, used only for that run: it writes a default output for a named platform that speclayer.json does not already cover, without changing the stored configuration.

status

Compare the local copy with the published library without writing files. Exit code 2 means the copy is behind or no local pull exists yet.

Check published freshness
npx spec-layer status

This checks the published bundle, not unpublished Figma changes. If you changed output selection or token settings, run pull to apply them.

list

List every artifact in the last local pull, including its output path or an indication that it was not written separately, and a row per platform output. No network request or key is needed.

Inspect available artifacts
npx spec-layer list

show

Print one artifact from the local bundle. Components default to compact YAML; foundations default to the DTCG JSON document. Add --canonical for canonical Context JSON.

npx spec-layer show component Button
npx spec-layer show foundation
npx spec-layer show component Button --canonical
npx spec-layer show foundation --canonical

Quote names with spaces. An unknown or ambiguous component name produces an error rather than choosing a component for you. The command reads the full local bundle, even when the artifact was not selected for a separate file.

Selection flags

setup, init, and pull accept these options. They replace the configured selection for that command; they are not merged with it.

npx spec-layer pull --only foundation
npx spec-layer pull --only components
npx spec-layer pull --component Button --component "Text field"
npx spec-layer pull --only components --component Button
  • --only foundation writes foundation token files and no component YAML.
  • --only components excludes the foundation token directory.
  • --component NAME is repeatable and includes the foundation unless combined with --only components.
  • --only foundation cannot be combined with --component.

Names match by slug: Button matches button, and Icon Button matches icon-button. A name that matches nothing fails before output is written. The complete published bundle is still retained in bundle.json.

Exit codes

CodeMeaning
0Success. For status, the local copy matches the published library.
1Usage, configuration, key, component-name, network, or server error.
2Status only: local context is behind or no local pull exists.

Current commands are setup, init, pull, status, list, show, tools, and skill. There is no CLI validate, normalize, or diff command in this version.
