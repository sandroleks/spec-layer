# Plugin 2.0: Token-Aware Measure, States Matrix & Polish — Design

**Date:** 2026-07-05
**Status:** Approved for planning
**Scope:** `packages/plugin`, `packages/extractor`

## Context

The plugin ("Auto Guidelines & Specs", Figma Community ID 1652104411578396548) is live and accepted. Decision: the community plugin is the product for now; this release invests in making its documentation output best-in-class. The strategy pivot (drift detection, agent context) stays on the roadmap but is not designed for here.

Competitive research findings that shape this design:

- **EightShapes Specs / Specs 2** is the competitor to beat. It paywalls Figma variables detection, Tokens Studio support, nested-component specs, and tabular anatomy. Its top complaints are generation crashes and staleness. Our deterministic, condition-aware token extraction is free and deep — that is the wedge.
- **Missing states documentation** is the single most-cited handoff gap in designer literature; no generator addresses it.
- Static redline plugins are being displaced by Dev Mode native annotations; a measure section must be token-native, not just prettier vectors.
- Robustness is a marketable feature: Specs' top GitHub issues are crashes on real-world components.

Audience: broad (DS maintainers, handoff designers, agencies). Release shape: one "2.0" community release — two flagship features plus a polish pass.

## Feature 1 (flagship): Token-aware Measure section

A new "Measurements" section in the generated doc frame, placed between Anatomy and Configuration, toggleable in the section list.

**Rendering.** The default variant's screenshot at up to ~480px tall (larger than the anatomy image, so annotations have room), overlaid with:

- **Padding** — bracket lines on each inside edge with a label chip per edge. Reuses the existing collapse logic: one chip when all sides match, `x`/`y` pairs when horizontally/vertically symmetric.
- **Gap** — markers between auto-layout children.
- **Size** — width/height dimension lines outside the bounding box.
- **Corner radius** — a corner callout when radius is non-zero.

**Token-first labels.** A chip reads `spacing/md · 12` when the value is bound to a variable, and just `12` in a visually distinct "unbound" style when raw. Unbound styling doubles as a hygiene signal consistent with the extraction-gaps section.

**Color semantics** are fixed (not brand-themed): green = padding, blue = element size, orange = gap. These match the Chrome-Inspector/Specs convention designers already know.

**Data flow.** Token bindings come from existing extractor rules (padding/gap/radius conditions already extracted in `packages/extractor/src/tokens.ts`). Geometry comes from the live node's child bounding boxes at frame-build time, same mechanism as anatomy pins. New rendering module: `packages/plugin/src/measureSection.ts` plus a small geometry helper.

**Scope guard.** Measure only the component root's auto-layout, plus first-level parts that have their own auto-layout. No deep recursive measurement in v1.

**Fallback.** If screenshot export fails, fall back to the existing measurements table (current behavior), matching the anatomy degradation pattern.

## Feature 2 (flagship): States matrix

A new "States" section rendered after the Variants section, auto-populated from variant data.

**Detection** (in `packages/extractor`, pure functions over serialized nodes):

- An axis is state-like when its name matches `state`/`status` (case-insensitive), **or** its values overlap a known vocabulary: `default, hover, focus, active, pressed, selected, disabled, error, loading, empty, readonly, visited`.
- Boolean component properties named `disabled`, `loading`, `error`, etc. count as single-value state columns.

**Rendering** (new module `packages/plugin/src/statesSection.ts`):

- Grid of live instance previews. Columns = detected states, ordered by conventional lifecycle (default → hover → focus → active → disabled → error/loading → unrecognized). Rows = the most significant non-state axis, capped at 4 rows; beyond the cap, render the default row plus a note, with the user's variant-picker selections deciding which rows appear.
- Cells reuse the per-variant card preview machinery.
- **Token-delta lines** below the grid: one line per state naming what changes vs. default, computed from the token diff (e.g., "**Hover** — background: `color/action-hover`"). This is the differentiator — no other plugin names the token deltas that define states.

**No state axis:** the section auto-hides from the generated frame; the section checkbox in the UI shows a muted hint ("no state variants detected").

**Fallbacks.** Per-cell preview failure shows the existing placeholder; token-delta lines render regardless (pure extraction data).

## Feature 3 (polish): Anatomy depth

- Extractor walk deepens from one level to a bounded deep walk: up to 3 levels, stopping at nested-component boundaries (a nested component is one numbered part; its internals belong to its own spec). File: `packages/extractor/src/anatomy.ts`.
- Legend becomes hierarchy-aware (indentation).
- New optional **tabular anatomy** view, toggleable in the UI ("diagram / table / both"): columns for #, part name, layer type, nested component reference, and key token bindings pulled from existing token rules. This matches Specs' paid tier, free.
- Pin overlap handling: cluster colliding pins and offset with short leader lines.

## Feature 4 (polish): Variant table refinements

1. **Diff highlighting** — default variant is the baseline; other variants' rows whose token differs from baseline get a subtle highlight; identical rows collapse behind a "same as default (n)" row.
2. **Resolved values alongside tokens** — typography as `font/label-md · Inter Semibold 14/20`, measurements as `spacing/sm · 8`. Tokens primary, resolved values muted suffixes.
3. **Unbound values included** — raw hardcoded values appear in the same "unbound" style as the Measure section instead of being omitted.

## Feature 5 (polish): Branding upgrades

Settings grows from two colors to a compact theme editor:

- **Fonts** — heading and body family chosen from fonts available in the file; async load, fall back to Inter on failure.
- **Palette** — header background, accent, body text, table header background. 3–4 curated presets; current navy/teal becomes the "Default" preset.
- **Logo** — "Use selected node as logo": user selects any frame/component on canvas, plugin exports it to PNG bytes stored in `clientStorage`, rendered top-right in the header band. No file uploads.
- All theme settings persist in `clientStorage`; "Reset to default" per group.

Measure/gap/padding annotation colors remain fixed semantic colors and are not part of theming.

## Plugin UI changes

- Section checkbox list gains **Measurements** and **States**, both on by default. States shows the muted hint when no state axis is detected.
- Anatomy gains a "diagram / table / both" toggle.
- Settings tab reorganized into three groups: AI, Theme (presets + palette + fonts + logo), reset affordances. Two-tab structure unchanged.

## Error handling

Every new renderer follows the established graceful-degradation pattern:

- Screenshot failure → tabular fallback.
- Font load failure → Inter.
- Logo missing/corrupt → header renders without it.
- No state axis → section hides.
- A frame build never fails because a new section failed; worst case the section is skipped and noted in extraction gaps.

Robustness is part of the release story (Specs' top complaint is crashes).

## Testing

- **Unit tests** in `packages/extractor` for: state-axis detection, deep anatomy walk (depth bound, nested-component stop), diff-vs-baseline computation.
- **Manual canvas matrix** for rendering: small component (icon button); large set (5 types × 6 states); component without auto-layout; component without a state axis; component with unbound values.
- New canvas builders go in new files (`measureSection.ts`, `statesSection.ts`) — `docFrame.ts` (1,076 lines) does not grow further.

## Build order (cut-scope-late sequencing)

1. Measure section
2. Variant table refinements
3. Anatomy depth
4. States matrix
5. Branding upgrades

One "2.0" community release; Measure and States screenshots headline the listing update.

## Out of scope

- Deep recursive measurement below first-level parts.
- Accessibility section generation (candidate flagship for the next release).
- Drift detection, coverage dashboard, agent-context outputs (strategy pivot — separate track).
- Tokens Studio detection (noted as Specs' most-requested integration; revisit after 2.0).

**Amendment (2026-07-05, final after three test iterations):** The Measure section uses the Spectral DesignDoc visual language: solid colored value badges (red = size, pink = padding, blue = gap) arranged in rails outside the artwork (right rail = layout-axis rhythm incl. child sizes, bottom rail = cross measurements, top/left = total dimensions), full-span translucent bands with dashed boundaries over padding/gap regions, dashed child outlines, and a quiet token-bindings line beneath the diagram carrying the token-first data (incl. radius). Supersedes both the semantic-color-chip and monochrome-pill designs.
